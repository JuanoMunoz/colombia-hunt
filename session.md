- T38: retirar categorías estáticas del hero; los filtros y el carrusel muestran únicamente el catálogo del backend más el filtro local "Todos". Los controles usan desplazamiento inmediato con `scroll-snap` y conservan el gesto horizontal táctil.

- `AGENTS.md` (mayúsculas) es el archivo canónico —en Windows `agents.md` colisiona con él, por eso no se crea duplicado en minúsculas.
- `checklist.md` y `session.md` en minúsculas, como pidió el usuario.
- Formatos fijados: checklist como tabla `ID | Task | Subtarea | Estado | Verificación`; session con secciones fijas + auditoría con fecha.
- `design.md` parte de los valores reales actuales (`app/globals.css`, `app/layout.tsx`, `app/page.tsx`) y deja `TBD` lo pendiente para que el usuario lo defina.
- Skills UI/UX en `.agents/skills` (antislop-ui, laws-of-ux, marketing-psychology, seo-audit, turso-cloud): `AGENTS.md` obliga a cargarlas antes de trabajo visual; T17 no era visual, pendientes de invocar.

- Para T19 se cargaron `antislop-ui` y `laws-of-ux`; el skill refiere a `antislop.md` core, pero no existe en el workspace, así que se siguieron la skill UI disponible y `design.md`.
- Para T19/T20 se cargaron `antislop-ui` y `laws-of-ux`; el skill refiere a `antislop.md` core, pero no existe en el workspace, así que se siguieron la skill UI disponible y `design.md`.
- Los proyectos se mantienen como mocks sin cambios de esquema; el index muestra solo imagen, título, autor pequeño, perfiles opcionales y likes locales.
- La ruta `[city]` solo acepta slugs de `KNOWN_CITIES`; segmentos desconocidos terminan en `app/not-found.tsx`.
- Estructura production-grade elegida (doc oficial + guías SaaS): `app/` solo rutas+api+i18n+lib(auth)+fonts; `components/ui` primitivas, `components/layout` Navbar, `components/sections` contenido de rutas; `public/img` logos; se respetan `lib/backend/`, `db/`, `app/lib/` del usuario. Sin route groups (URLs estables) ni carpetas vacías.
- `pnpm build` wrapper roto en este entorno → usar `pnpm exec next build` / `pnpm exec eslint`.
- `projects.livecode_url` es opcional y se mapea al campo Drizzle `livecodeUrl`; el seed usa parámetros SQL y `unixepoch()` para satisfacer los timestamps `NOT NULL`.
- `profiles.role` solo admite `user`/`admin` y cae en `user` por defecto. Las escrituras de catálogos requieren sesión y `admin`; el rol se aprovisiona directamente en la base de datos, nunca vía endpoint.
- La API de catálogos se implementa con Route Handlers, no Server Actions; `GET` es público y `POST`/`PUT`/`DELETE` requieren `admin`.
- `projects.deleted` es booleano `NOT NULL` con default `false`; `deletedAt` guarda la fecha de baja lógica. El DELETE permite al creador o admin; no elimina filas ni relaciones y las consultas compartidas omiten los borrados.
